# 회의록 자동 작성 서비스 FRD (MVP)

- 작성일: 2026-09-26
- 근거 문서: `docs/01_PRD.md`, `design/01_PC.html` · `02_Tablet.html` · `03_Mobile.html`
- 상태: 확정 (결정 기록은 7장)
- 변경 기록: 2026-09-27 EPIC 9-3에서 D3·TRD 결정으로 달라진 점(F7·F10 발송 결과, F11 메일 보관)을 반영하고 8-1에 "구현" 칸을 추가함 (결정 기록 ⑳)
- FRD(기능 요구사항 문서): 사용자가 무엇을 하면 서비스가 무엇을 하고, 어떤 결과가 나오는지를 기능별로 적은 문서입니다. 기술과 구현 방법은 이 문서에서 정하지 않습니다.

### 용어

| 용어 | 뜻 |
|---|---|
| 스크립트 | 녹음을 글로 옮긴 전체 내용입니다 |
| 화자 분리 | 목소리를 구분해 발언마다 말한 사람을 나누는 것입니다. 이름을 모르면 "화자1, 화자2"로 적습니다 |
| 타임스탬프 | 녹음 안의 위치입니다. 1시간 미만은 `[12:34]`, 1시간 이상은 `[1:02:03]`로 적습니다 |
| 근거 | 결정사항과 할 일이 나온 발언의 타임스탬프입니다 |
| 미정 | 녹음에서 확인되지 않아 비워 둔 값입니다. 담당자, 기한, 일시, 참석자에 씁니다 |
| 없음 | 해당하는 내용이 하나도 없는 항목입니다. 요약, 결정사항, 할 일에 씁니다 |
| 가림 | 개인정보 번호를 `***`로 바꿔 보이지 않게 하는 것입니다 |
| 방식 A / 방식 B | A는 "검토 후 보내기", B는 "바로 보내기"입니다 |
| 칩 | 입력한 이름이나 주소가 입력칸 위에 하나씩 작은 상자로 쌓이는 표시입니다. 칩마다 빼기(×) 버튼이 있습니다 |

## 1. 전체 사용 순서

```
[접속 암호 화면] 팀 공용 암호 입력 (처음 한 번)
   │
   ▼
[처음 화면] 보내는 방식 고르기: 방식 A 카드 / 방식 B 카드
   │
   ▼
[올리기 화면] ① 녹음 파일(필수) ② 회의 정보(선택) ③ 받는 메일 주소(필수)
   │           방식 탭으로 A/B를 바꿀 수 있음
   │
   ├─ 방식 A: 검토 후 보내기 ──────────────────────────────────────────
   │   「회의록 만들기」
   │   → [처리 중 화면] 녹음 파일 올리기 → 스크립트 만들기 → 회의록 만들기
   │   → [확인 화면] 구역별 「고치기」 · 「.md 내려받기」
   │   → 「메일 보내기」 → [발송 확인 창] → 「보내기」
   │   → [보낸 결과 화면] 주소별 결과 · 「.md 내려받기」 · 「새 회의록 만들기」
   │
   └─ 방식 B: 바로 보내기 ────────────────────────────────────────────
       「올리고 바로 보내기」
       → [주소 확인 창] 「주소 고치기」 또는 「이 주소로 올리고 보내기」
       → [처리 중 화면] 녹음 파일 올리기 → 스크립트 만들기 → 회의록 만들기 → 메일 보내기
         (사람이 아무것도 하지 않아도 끝까지 진행)
       → [발송 결과 화면] 주소별 결과 · 「.md 내려받기」 · 「새 회의록 만들기」

공통: 상단 「처음으로」 → [나가기 확인 창] 「머무르기」 또는 「처음으로」
실패: 처리 중 화면에서 실패한 단계를 보여 주고 「다시 시도」 또는 「처음으로」
```

### 화면 목록

| 화면 | 들어오는 때 | 주요 버튼 |
|---|---|---|
| 접속 암호 화면 | 이 기기에서 처음 접속할 때, 암호를 입력한 지 30일이 지났을 때 | 「들어가기」 |
| 처음 화면 | 접속 직후, 「처음으로」를 누른 뒤 | 「검토 후 보내기로 시작」, 「바로 보내기로 시작」 |
| 올리기 화면 | 처음 화면에서 방식을 고른 뒤 | 방식 탭, 파일 고르기, 「추가」, 「회의록 만들기」 또는 「올리고 바로 보내기」 |
| 처리 중 화면 | 올리기를 시작한 뒤 | 실패했을 때만 「다시 시도」, 「처음으로」 |
| 확인 화면 (A) | 방식 A에서 회의록이 만들어진 뒤 | 「고치기」, 「.md 내려받기」, 「메일 보내기」, 「처음으로」 |
| 보낸 결과 화면 (A) | 방식 A에서 메일을 보낸 뒤 | 「.md 내려받기」, 「새 회의록 만들기」, 실패 주소가 있으면 「실패한 주소에 다시 보내기」 |
| 발송 결과 화면 (B) | 방식 B에서 자동 발송이 끝난 뒤 | 위와 같음 |

창(작은 확인 상자): 파일 선택 창, 주소 확인 창(B), 발송 확인 창(A), 나가기 확인 창.

## 3. 공통 규칙

### 3-1. 녹음에서 확인할 수 없는 내용의 표시

AI는 녹음에서 확인되지 않는 내용을 지어내지 않습니다. 빈 값은 아래처럼 표시합니다.

| 항목 | 확인되지 않을 때 | 표시 |
|---|---|---|
| 제목 | 입력하지 않으면 AI가 녹음 내용을 바탕으로 짓습니다 | 항상 값이 있습니다 |
| 일시 | 입력도 없고 파일에 담긴 녹음 시각도 없을 때 | `미정` |
| 참석자 | 아래 "참석자 연결 규칙"을 따릅니다 | 이름 또는 `화자N`. 녹음에서 말한 사람을 찾지 못하면 `미정` |
| 요약 | 녹음에 논의 내용이 없을 때, 검토에서 모두 지웠을 때 | `없음` |
| 결정사항 | 녹음에서 합의된 것이 없을 때 | `없음` |
| 할 일 | 녹음에서 맡긴 일이 없을 때 | `없음` |
| 할 일의 담당자·기한 | 녹음에서 확인되지 않을 때 | `미정` |
| 결정사항·할 일의 근거 | AI가 만든 것은 항상 있습니다. 검토에서 사람이 비웠을 때만 빕니다 | `근거 없음` |

- **화면:** `미정`, `없음`, `근거 없음`은 점선 상자로 표시해 녹음에서 나온 값과 구분합니다.
- **`.md` 파일과 메일:** 같은 낱말을 일반 글자로 적습니다.

**참석자 연결 규칙**
- 입력한 이름은 녹음 속 호칭(예: "지은 님")과 연결해, 스크립트에서 그 사람의 발언에 이름을 붙입니다.
- 연결이 확실하지 않은 목소리는 추측하지 않고 `화자N`으로 둡니다.
- 입력한 이름은 목소리와 연결되지 않아도 참석자 줄에 모두 적습니다. 말하지 않은 참석자일 수 있기 때문입니다.
- 이름을 입력하지 않으면 녹음에서 이름이 확인되는 사람은 그 이름을, 아니면 `화자N`을 씁니다.
- 참석자 줄의 순서는 입력한 이름 먼저, 그다음 `화자N`입니다.

**"수정됨" 표시 (방식 A에서 사람이 고친 부분)**
- 검토에서 고치거나 새로 추가한 줄 끝에 `(수정됨)`을 붙입니다. 대상은 제목, 일시, 참석자, 요약 한 줄, 결정사항 한 개, 할 일 한 줄입니다.
- 지운 줄은 흔적을 남기지 않습니다.
- `(수정됨)`은 화면, `.md` 파일, 메일에 모두 똑같이 나옵니다.

**"AI 작성" 안내 문구**
- `.md` 파일 끝과 메일 본문 끝에 아래 문구를 넣습니다.
  > 이 회의록은 녹음을 바탕으로 AI가 작성했습니다. `(수정됨)` 표시는 검토자가 고친 부분입니다.
- 둘째 문장은 `(수정됨)`이 하나라도 있을 때만 넣습니다.
- 화면에서는 회의록 맨 아래에 같은 문구를 보여 줍니다.

### 3-2. 개인정보 가림 (F12)

- **대상:** 형식이 뚜렷한 번호 네 가지입니다. 주민등록번호, 전화번호(휴대전화·일반전화), 계좌번호, 카드번호.
- **범위:** 스크립트, 요약, 결정사항, 할 일 전체입니다. 화면, `.md` 파일, 메일에 모두 가린 상태로 나옵니다. 전체 스크립트를 원본 그대로 두는 원칙의 유일한 예외입니다.
- **방법:** 번호 전체를 `***`로 바꿉니다. 발언의 나머지 글과 타임스탬프는 그대로 둡니다.
- **사람이 고친 내용:** 방식 A에서 「적용」을 누를 때 같은 규칙을 다시 적용합니다. 검토자가 번호를 직접 적어도 밖으로 나가지 않습니다.
- **안내:** 1건 이상 가렸으면 전체 스크립트 제목 옆에 "개인정보 번호 N건을 가렸습니다"를 표시합니다.
- **한계:** 이름, 주소, 말로 풀어 읽은 번호(예: "공일공 일이삼사")는 가리지 못할 수 있습니다. 이 한계를 처음 화면의 "회의록은 이렇게 만듭니다"에 한 줄로 알립니다.

### 3-3. 보관하지 않음 (F11)

- 처음 화면 "회의록은 이렇게 만듭니다"에 "녹음은 Google AI(Gemini)로 처리한 뒤 바로 삭제합니다."를 안내합니다.
- 녹음 파일은 스크립트 만들기가 끝나거나 실패하는 즉시 서비스에서 삭제합니다.
- 회의록은 아래 중 먼저 일어나는 때에 삭제합니다.
  - 결과 화면을 나갈 때 (「처음으로」, 「새 회의록 만들기」, 창 닫기, 새로고침)
  - 회의록이 만들어지고 24시간이 지났을 때
- 서비스에는 회의록 목록이나 검색이 없습니다. 기록은 보낸 메일과 내려받은 `.md` 파일로만 남습니다.
- 보낸 메일 자체는 서비스가 아니라 전용 Gmail 계정에 남습니다. 30일이 지난 메일은 매일 도는 청소가 IMAP으로 Gmail의 휴지통으로 옮겨 지웁니다. Gmail 필터는 메일이 며칠 지났는지로 고를 수 없어, 필터 대신 이 방법을 씁니다.

### 3-4. 중복 발송 막기

- 한 번 만든 회의록은 **받는 주소마다 최대 한 번만** 발송에 성공합니다.
- 발송이 시작되는 버튼(「보내기」, 「이 주소로 올리고 보내기」, 「실패한 주소에 다시 보내기」)은 누르는 즉시 막히고 "보내는 중"으로 바뀝니다. 여러 번 눌러도 한 번만 처리합니다.
- 보낸 결과 화면에는 전체를 다시 보내는 버튼이 없습니다. 발송에 실패한 주소만 다시 보낼 수 있습니다.
- 결과 화면에서 뒤로 가기를 해도 확인 화면으로 돌아가지 않습니다.
- 방식 B에서 처리 중에 새로고침하거나 창을 닫아도 메일은 한 번만 나갑니다(4장 F10 참고).
- 같은 녹음 파일을 다시 올리는 것은 새 회의록으로 보고 막지 않습니다.

### 3-5. 입력 제한

| 항목 | 제한 |
|---|---|
| 녹음 형식 | mp3, m4a, wav |
| 녹음 크기 | 200MB 이하 |
| 녹음 길이 | 2시간 이하 |
| 지원 언어 | 한국어 회의. 섞여 나온 영어 단어나 문장은 들린 그대로 적습니다. 한국어가 거의 없는 녹음은 결과를 보장하지 않습니다(오류로 막지는 않음) |
| 받는 사람 수 | 1명 이상 20명 이하 |

## 4. 기능 상세

각 기능은 **시작 조건·입력 → 프로그램 동작 → 화면·파일·메일 결과 → 오류 안내 → 직접 확인할 기준** 순서로 적습니다.

### F13. 접속 암호 확인

**시작 조건·입력**
- 이 기기에서 처음 서비스 주소를 열었을 때, 또는 암호를 입력한 지 30일이 지났을 때 나옵니다.
- 입력: 팀 공용 암호.

**프로그램 동작**
- 암호가 맞으면 처음 화면을 엽니다. 이 기기에서는 30일 동안 다시 묻지 않습니다.
- 팀에서 암호를 바꾸면 모든 기기에서 다시 묻습니다.
- 5번 연속 틀리면 10분 동안 입력을 막습니다.

**화면·파일·메일 결과**
- 화면: 서비스 이름, 암호 입력칸, 「들어가기」. 파일과 메일은 없습니다.

**오류 안내**
- 틀림: "암호가 맞지 않습니다."
- 잠김: "여러 번 틀려 10분 동안 입력할 수 없습니다."

**직접 확인할 기준**
- [ ] 암호 없이 서비스 주소를 열면 처음 화면이 아니라 암호 화면이 나온다.
- [ ] 맞는 암호를 넣으면 처음 화면이 열리고, 같은 기기에서 다시 열어도 묻지 않는다.
- [ ] 5번 틀리면 10분 동안 입력이 막힌다.

> 시안에 없는 화면입니다. 8장 "시안에 더할 것"에 올려 두었습니다.

### F4. 보내기 방식 선택

**시작 조건·입력**
- 처음 화면에서 방식 A 카드(「검토 후 보내기로 시작」) 또는 방식 B 카드(「바로 보내기로 시작」)를 누릅니다.
- 올리기 화면에서는 위쪽의 방식 탭("검토 후 보내기" / "바로 보내기")으로 언제든 바꿀 수 있습니다.

**프로그램 동작**
- 고른 방식으로 올리기 화면을 엽니다.
- 탭을 바꿔도 이미 입력한 파일, 회의 정보, 받는 주소는 그대로 둡니다.
- 방식은 올리기를 시작하는 순간 정해지며, 그 뒤에는 바꿀 수 없습니다.

**화면·파일·메일 결과**
- 머리글에 방식 표시가 나옵니다(파란색 "검토 후 보내기" 또는 주황색 "바로 보내기"). 처음 화면을 뺀 모든 화면에 나옵니다.
- 방식 A를 고르면 안내가 나옵니다: "회의록이 만들어지면 확인 화면이 열립니다. 내용을 확인하고 필요하면 고친 뒤 직접 보냅니다."
- 방식 B를 고르면 경고가 나옵니다: "회의록이 만들어지면 사람의 검토 없이 곧바로 메일이 나갑니다. 올리기 전에 받는 주소를 한 번 더 보여 드립니다." 받는 주소 구역에도 주황색 테두리와 경고가 붙습니다.
- 올리기 버튼 이름이 바뀝니다. A는 「회의록 만들기」, B는 「올리고 바로 보내기」입니다.

**오류 안내**
- 없음.

**직접 확인할 기준**
- [ ] 처음 화면의 두 카드가 각각 해당 방식이 선택된 올리기 화면을 연다.
- [ ] 파일과 주소를 넣은 뒤 탭을 바꿔도 입력값이 남아 있다.
- [ ] B를 고르면 경고 문구와 「올리고 바로 보내기」 버튼이 보인다.

### F1. 녹음 파일 올리기

**시작 조건·입력**
- 올리기 화면 ① 녹음 파일 구역(필수)에서 입력합니다.
- PC·태블릿에서는 파일을 끌어다 놓거나 눌러서 고릅니다. 모바일에서는 "눌러서 녹음 파일 고르기"만 있습니다.
- 한 번에 파일 1개만 고를 수 있습니다.

**프로그램 동작**
- 고르는 즉시 형식(확장자)과 크기를 검사합니다. 올리기는 아직 하지 않습니다.
- 「다른 파일」(PC·태블릿)을 누르면 새 파일로 바꿉니다. 빼기(×)를 누르면 고른 파일을 지웁니다.
- 올리기 버튼을 누르면 파일, 받는 주소, 입력 중인 주소를 한꺼번에 검사합니다(F3 참고). 문제가 없을 때만 올리기를 시작합니다.
- 녹음 길이는 고를 때 알 수 있으면 그때 검사하고, 알 수 없으면 처리 중에 검사합니다.

**화면·파일·메일 결과**
- 파일을 고르면 파일 이름과 "m4a 파일 · 아직 올리지 않았습니다"가 표시됩니다.
- PC 오른쪽 "보내기 전 확인" 패널의 녹음 파일 칸에 파일 이름이 나옵니다(고르기 전에는 "아직 고르지 않았습니다").
- 처리 중 화면 맨 위에 파일 이름이 나오고, "녹음 파일 올리기" 단계가 완료로 바뀝니다.
- 처리 중 화면에 "녹음 파일은 처리가 끝나면 서비스에서 삭제됩니다."를 표시합니다.

**오류 안내**

| 상황 | 표시 위치 | 안내 문구 |
|---|---|---|
| 파일 없이 올리기 버튼을 누름 | 파일 구역 (빨간 테두리) | "녹음 파일을 올려 주세요." |
| 지원하지 않는 형식 | 파일 구역 (빨간 파일 표시) | "지원하지 않는 형식입니다(.mp4). mp3, m4a, wav 파일을 올려 주세요." |
| 200MB 초과 | 파일 구역 | "파일이 너무 큽니다. 200MB 이하 파일을 올려 주세요." |
| 2시간 초과 | 파일 구역 또는 처리 중 화면 | "녹음이 2시간을 넘습니다. 2시간 이하로 나눠서 올려 주세요." |
| 올리는 중 연결이 끊김 | 처리 중 화면 | "파일을 올리지 못했습니다. 인터넷 연결을 확인하고 다시 시도해 주세요." |

형식이 맞지 않는 파일을 고른 상태에서는 올리기 버튼을 눌러도 진행하지 않습니다.

**직접 확인할 기준**
- [ ] mp3, m4a, wav 파일은 각각 받아들이고, mp4 같은 다른 형식은 위 문구로 거절한다.
- [ ] 200MB가 넘는 파일, 2시간이 넘는 녹음은 거절한다.
- [ ] 파일 없이 버튼을 누르면 파일 구역에 오류가 나오고 다음 화면으로 넘어가지 않는다.
- [ ] 빼기(×)를 누르면 다시 파일을 고르는 상태로 돌아간다.

### F2. 회의 정보 선택 입력

**시작 조건·입력**
- 올리기 화면 ② 회의 정보 구역에서 입력합니다. 세 칸 모두 선택 사항입니다.
  - **제목:** 글자 입력. 예시 "신규 기능 출시 일정 회의"
  - **일시:** 날짜와 시각 선택
  - **참석자 이름:** 이름을 쓰고 Enter, 쉼표, 「추가」 중 하나로 칩을 만듭니다. 칩의 ×로 뺍니다.

**프로그램 동작**
- 한글을 입력하는 중(글자 조합 중)에 누른 Enter는 칩을 만들지 않고 글자만 확정합니다.
- 이미 있는 이름을 다시 추가하면 칩을 더 만들지 않고 입력칸만 비웁니다.
- 빈 칸은 회의록을 만들 때 아래처럼 채웁니다(3-1 참고).
  - 제목이 비면 AI가 녹음 내용으로 짓습니다.
  - 일시가 비면 파일에 담긴 녹음 시각을 쓰고, 그것도 없으면 `미정`으로 둡니다.
  - 참석자가 비면 녹음에서 확인된 이름 또는 `화자N`을 씁니다.

**화면·파일·메일 결과**
- 칸마다 빈 칸일 때의 처리를 안내합니다. 예: "비우면 AI가 녹음 내용을 바탕으로 짓습니다."
- 입력한 값은 회의록 머리의 제목, 일시, 참석자 줄로 들어가고, 파일 이름과 메일 제목에도 쓰입니다.

**오류 안내**
- 없음. 모두 비워도 진행합니다.

**직접 확인할 기준**
- [ ] 세 칸을 모두 비워도 회의록이 만들어진다.
- [ ] 제목을 입력하면 회의록, 메일 제목, 파일 안의 제목이 입력값과 같다.
- [ ] 일시를 비우고 녹음 시각이 없는 파일을 올리면 일시가 `미정`이다.
- [ ] 한글 이름을 쓰다가 Enter를 누르면 글자가 잘리지 않고 칩 하나로 들어간다.

### F3. 받는 메일 주소 입력

**시작 조건·입력**
- 올리기 화면 ③ 받는 메일 주소 구역(필수)에서 입력합니다.
- 주소를 쓰고 Enter, 쉼표, 「추가」 중 하나로 칩을 만듭니다. 칩의 ×로 뺍니다.

**프로그램 동작**
- 추가할 때마다 주소 형식을 검사합니다. `이름@도메인.끝` 형태가 아니면 받지 않습니다.
- 이미 있는 주소는 다시 받지 않습니다.
- 올리기 버튼을 누를 때 입력칸에 남아 있는 주소도 자동으로 추가를 시도합니다.
- 방식 A에서는 받는 주소를 올릴 때 정하고, 확인 화면에서는 바꿀 수 없습니다("올릴 때 입력한 주소입니다" 표시). 바꾸려면 처음으로 돌아가 다시 만들어야 합니다.

**화면·파일·메일 결과**
- PC 오른쪽 "보내기 전 확인" 패널에 "받는 사람 N명"과 주소 목록이 나옵니다(없으면 "아직 없습니다").
- 태블릿·모바일에서는 화면 아래 고정 막대에 "받는 사람 N명"이 나옵니다.
- 이 주소들이 메일 수신자가 됩니다. 모두 "받는 사람"으로 넣으므로 수신자끼리 서로의 주소가 보입니다.

**오류 안내**

| 상황 | 안내 문구 |
|---|---|
| 형식이 틀림 (입력칸 빨간 테두리) | "메일 주소 형식이 아닙니다. 예: name@company.com" |
| 같은 주소를 또 추가 | "이미 추가한 주소입니다." |
| 주소 없이 올리기 버튼을 누름 | "받는 메일 주소를 1개 이상 입력해 주세요." |
| 21번째 주소를 추가 | "받는 사람은 20명까지 넣을 수 있습니다." |

- 입력칸에 글자를 다시 쓰기 시작하면 형식 오류 표시는 사라집니다.
- 실제로 없는 주소인지는 여기서 알 수 없습니다. 발송 때 알게 되며 F10에서 다룹니다.

**직접 확인할 기준**
- [ ] 주소 3개를 넣으면 칩 3개와 "받는 사람 3명"이 보인다.
- [ ] `jieun.lee@example`처럼 틀린 형식은 칩이 되지 않고 오류가 나온다.
- [ ] 입력칸에 주소를 쓰고 추가하지 않은 채 올리기 버튼을 눌러도 그 주소가 포함된다.
- [ ] 21번째 주소는 추가되지 않는다.

### F5. 스크립트 만들기

**시작 조건·입력**
- 올리기가 끝나면 자동으로 시작합니다. 입력은 녹음 파일과 참석자 이름입니다.

**프로그램 동작**
- 녹음을 글로 옮깁니다(음성 인식).
- 목소리로 말한 사람을 나누고(화자 분리), 참석자 연결 규칙(3-1)에 따라 이름 또는 `화자N`을 붙입니다.
- 발언마다 시작 위치의 타임스탬프를 붙입니다.
- 개인정보 번호를 가립니다(3-2).
- 끝나거나 실패하는 즉시 녹음 파일을 삭제합니다.

**화면·파일·메일 결과**
- 처리 중 화면의 "스크립트 만들기" 단계가 "진행 중"에서 "완료"로 바뀝니다.
- 결과 화면과 `.md` 파일의 "전체 스크립트"에 발언마다 `[타임스탬프] 이름(또는 화자N): 내용` 형식으로 들어갑니다.
- 메일 본문에는 넣지 않습니다(첨부 파일에만 있음).

**오류 안내**

| 상황 | 안내 문구 |
|---|---|
| 파일을 읽을 수 없음 | "녹음을 읽을 수 없습니다. 파일이 손상되었을 수 있습니다. 다른 파일로 다시 올려 주세요." |
| 말소리가 없음 | "녹음에서 말소리를 찾지 못했습니다. 파일을 확인해 주세요." |
| 그 밖의 처리 실패 | "스크립트를 만들지 못했습니다. 잠시 뒤 다시 시도해 주세요." |

실패하면 F6·F10을 진행하지 않습니다. 방식 B라도 메일은 나가지 않습니다(4장 "처리 실패" 참고).

**직접 확인할 기준**
- [ ] mp3, m4a, wav 시험 녹음에서 모두 스크립트가 나온다.
- [ ] 모든 발언 앞에 타임스탬프와 말한 사람이 있다.
- [ ] 목소리가 3명인 녹음에서 입력하지 않은 사람은 `화자N`으로 나온다.
- [ ] 스크립트 속 전화번호가 `***`로 나온다.
- [ ] 처리가 끝난 뒤 녹음 파일이 서비스에 남아 있지 않다.

### F6. 회의록 만들기

**시작 조건·입력**
- 스크립트가 만들어지면 자동으로 시작합니다. 입력은 스크립트와 회의 정보(제목, 일시, 참석자)입니다.

**프로그램 동작**
- PRD 5장 양식과 작성 규칙에 따라 제목, 일시, 참석자, 요약, 결정사항, 할 일을 만듭니다.
- **요약:** 녹음 내용만으로 짧게 씁니다. 타임스탬프는 붙이지 않습니다.
- **결정사항:** 녹음에서 합의된 것만 적고, 합의한 발언의 타임스탬프를 붙입니다.
- **할 일:** 맡긴 일마다 담당자, 기한, 근거 타임스탬프를 적습니다. 녹음에서 확인되지 않는 담당자나 기한은 `미정`으로 둡니다.
- 녹음에 없는 날짜나 담당자를 짐작해서 채우지 않습니다.
- 전체 스크립트는 F5 결과를 바꾸지 않고 그대로 붙입니다.

**화면·파일·메일 결과**
- 처리 중 화면의 "회의록 만들기" 단계가 완료로 바뀝니다.
- 방식 A는 확인 화면으로 자동으로 넘어갑니다. 방식 B는 곧바로 F10 발송으로 넘어갑니다.

**오류 안내**
- 실패: "회의록을 만들지 못했습니다. 잠시 뒤 다시 시도해 주세요."
- 결정사항이나 할 일이 없는 것은 오류가 아닙니다. `없음`으로 표시합니다.

**직접 확인할 기준**
- [ ] 회의록에 제목, 일시, 참석자, 요약, 결정사항, 할 일, 전체 스크립트가 모두 있다.
- [ ] 기한을 말하지 않은 할 일이 있는 녹음에서 기한이 `미정`으로 나온다.
- [ ] 결정사항과 할 일의 타임스탬프 위치에 실제로 근거가 되는 발언이 있다.
- [ ] 실제 팀 회의 녹음 3건에서 결정사항과 할 일이 녹음과 어긋나지 않는다.

### 처리 중 화면과 처리 실패 (F5·F6·F10 공통)

**시작 조건·입력**
- A는 「회의록 만들기」, B는 주소 확인 창의 「이 주소로 올리고 보내기」를 누르면 열립니다.

**프로그램 동작**
- 단계를 차례로 진행하고, 단계마다 상태를 "대기 → 진행 중 → 완료" 또는 "실패"로 바꿉니다.
  - A: 녹음 파일 올리기 → 스크립트 만들기 → 회의록 만들기
  - B: 위 세 단계 → 메일 보내기
- 한 단계라도 실패하면 거기서 멈춥니다.
- 「다시 시도」를 누르면 창에 남아 있는 같은 파일과 입력값으로 처음 단계부터 다시 진행합니다. 방식 B라도 주소 확인 창을 다시 띄우지 않습니다.
- 「처음으로」를 누르면 입력값을 모두 버리고 처음 화면으로 갑니다.

**창을 닫거나 새로고침할 때**

| 시점 | 방식 A | 방식 B |
|---|---|---|
| 녹음 올리는 중 | 확인을 묻고, 나가면 처리를 멈춥니다. 아무것도 남지 않습니다 | A와 같습니다. 메일은 나가지 않습니다 |
| 올리기가 끝난 뒤 | 확인을 묻고, 나가면 만들던 회의록을 버립니다 | 확인을 묻고, 나가도 서비스가 끝까지 처리해 메일을 보냅니다. 결과 화면은 다시 볼 수 없으니 메일로 확인합니다 |

- 확인 문구: "지금 나가면 만들던 회의록이 사라집니다." (B에서 올리기가 끝난 뒤에는 "나가도 메일은 보내집니다. 다만 결과 화면은 다시 볼 수 없습니다.")
- 새로고침하면 처음 화면이 열립니다. B의 처리와 발송은 한 번만 이어집니다(3-4).

**화면·파일·메일 결과**
- 제목: A는 "회의록을 만들고 있습니다", B는 "회의록을 만든 뒤 바로 보냅니다"
- B는 "회의록이 만들어지면 이 주소로 검토 없이 보냅니다"와 주소 목록을 함께 보여 줍니다. 그리고 다음을 안내합니다: "올리기가 끝나면 창을 닫아도 메일이 나갑니다. 다만 창을 닫으면 실패했을 때 알려 드릴 수 없습니다."
- A는 "회의록이 만들어지면 확인 화면이 열립니다. 메일은 아직 보내지 않습니다."를 안내합니다.
- 실패하면 실패한 단계에 빨간 "실패" 표시와 이유를 적고, 「다시 시도」와 「처음으로」를 보여 줍니다.

**방식 B의 실패 알림**
- 올린 사람의 메일 주소는 받지 않으므로 메일로는 알리지 않습니다. 처리 중 화면에서만 알립니다.
- 메일 보내기 전에 실패하면 어떤 메일도 나가지 않습니다.

**직접 확인할 기준**
- [ ] 단계 상태가 실제 진행에 맞춰 바뀐다.
- [ ] 스크립트 단계에서 일부러 실패시키면 B에서도 메일이 나가지 않는다.
- [ ] 「다시 시도」가 파일을 다시 고르지 않아도 처음부터 진행된다.
- [ ] B에서 올리기가 끝난 뒤 창을 닫아도 메일이 정확히 한 번 도착한다.

### F7. 결과 화면 보기

**시작 조건·입력**
- 확인 화면(A): 회의록 만들기가 끝나면 자동으로 열립니다.
- 보낸 결과 화면(A): 발송 확인 창에서 「보내기」를 누른 뒤 열립니다.
- 발송 결과 화면(B): 자동 발송이 끝나면 열립니다.

**프로그램 동작**
- 회의록을 PRD 5-1 양식 순서대로 보여 줍니다. 제목, 일시, 참석자, 요약, 결정사항, 할 일, 전체 스크립트, AI 작성 안내 순입니다.
- 확인 화면에서만 「고치기」를 보여 줍니다(F8). 보낸 결과 화면과 발송 결과 화면은 읽기 전용입니다.
- 전체 스크립트는 모든 화면에서 고칠 수 없습니다("고칠 수 없음" 자물쇠 표시).

**화면·파일·메일 결과**
- **맨 위 알림**
  - 확인 화면: "회의록을 확인하고, 필요하면 고친 뒤 보내세요"와 "직접 고친 내용은 검토자 책임으로 봅니다."
  - 보낸 결과 화면: "메일을 보냈습니다"와 받는 사람 수
  - 발송 결과 화면: "검토 없이 바로 보냈습니다"와 받는 사람 수
- **회의록 영역**
  - 맨 위에 파일 이름(`회의록_YYYY-MM-DD.md`)을 보여 줍니다.
  - 결정사항과 할 일 옆에는 근거 타임스탬프 `[mm:ss]`를 표시합니다.
  - `미정`, `없음`, `근거 없음`은 점선 상자로 표시합니다.
  - 할 일은 PC·태블릿에서 표(할 일 / 담당자 / 기한 / 근거), 모바일에서 카드로 보여 줍니다.
  - 전체 스크립트는 따로 스크롤되는 상자에 담습니다.
- **메일 정보** (PC는 오른쪽 패널, 태블릿·모바일은 회의록 위 상자)
  - "보낼 곳"(보낸 뒤에는 "보낸 곳")과 주소 목록을 보여 줍니다.
  - 메일 제목, 본문 구성, 첨부 파일 이름을 보여 줍니다.
- **보낸 뒤 화면의 주소별 결과:** 접수 직후에는 주소마다 "확인 중"이 표시되고, 최대 2분 안에 "보냄" 또는 "보내지 못함(이유)"으로 바뀝니다. "보낸 뒤 2분이 지나 반송되면 표시되지 않을 수 있습니다."를 함께 보여 줍니다(F10).
- **보관 안내:** "회의록은 서비스에 보관되지 않습니다. 이 화면을 나가면 다시 볼 수 없으니, 필요하면 지금 내려받으세요."

**오류 안내**
- 회의록이 만들어진 지 24시간이 지나면: "보관 시간(24시간)이 지나 회의록이 삭제되었습니다. 녹음을 다시 올려 주세요." 이후 보내기와 내려받기를 할 수 없고 「처음으로」만 남습니다.

**직접 확인할 기준**
- [ ] A와 B 모두 만들어진 회의록을 화면에서 볼 수 있다.
- [ ] 보낸 결과 화면과 발송 결과 화면에는 「고치기」가 없다.
- [ ] 화면의 파일 이름과 메일 제목이 5-3·5-4 규칙과 같다.

### F8. 검토 중 편집 (방식 A 확인 화면)

**시작 조건·입력**
- 확인 화면에서 네 구역의 「고치기」 중 하나를 누릅니다. 한 번에 한 구역만 고칠 수 있습니다.

| 구역 | 입력칸 | 추가·지우기 |
|---|---|---|
| 기본 정보 | 제목, 일시(글자, 예: 2026-09-22 14:00), 참석자(쉼표로 구분) | 없음 |
| 요약 | 줄마다 글자 칸 | 「줄 추가」, 줄 지우기(휴지통) |
| 결정사항 | 결정사항, 근거(mm:ss) | 「결정사항 추가」, 지우기 |
| 할 일 | 할 일, 담당자, 기한, 근거(mm:ss) | 「할 일 추가」, 지우기 |

**프로그램 동작**
- 「취소」를 누르면 고치기 전으로 되돌립니다.
- 「적용」을 누르면 아래 규칙대로 반영합니다.
  - **제목:** 비우면 원래 제목을 유지합니다.
  - **일시:** 비우면 `미정`입니다. 값이 있으면 `YYYY-MM-DD` 또는 `YYYY-MM-DD HH:MM` 형식이어야 합니다.
  - **참석자:** 비우면 `미정`입니다.
  - **내용이 빈 줄:** 요약·결정사항·할 일에서 내용이 빈 줄은 버립니다. 줄이 하나도 안 남으면 `없음`입니다.
  - **담당자·기한:** 비우면 `미정`입니다.
  - **근거:** 비우면 `근거 없음`입니다. 값이 있으면 `mm:ss` 또는 `h:mm:ss` 형식이어야 하고, 녹음 길이보다 뒤일 수 없습니다. 입력한 `[ ]`나 `` ` `` 기호는 지웁니다.
  - 바뀐 줄과 추가한 줄에 `(수정됨)`을 붙입니다(3-1).
  - 개인정보 가림 규칙을 다시 적용합니다(3-2).
- 고치는 중에는 「메일 보내기」가 막힙니다.
- 전체 스크립트는 고칠 수 없습니다.

**화면·파일·메일 결과**
- 고치는 구역은 파란 테두리 상자와 "OO 고치는 중" 제목으로 바뀝니다.
- 기본 정보를 고치는 중에는 일시 칸 아래에 바뀔 파일 이름을 미리 보여 줍니다.
- 적용한 내용은 화면, `.md` 파일, 메일 본문과 첨부에 그대로 들어갑니다.
- 고치는 중에는 보내기 버튼 아래에 "고치는 중인 항목을 먼저 적용하거나 취소하세요."가 나옵니다.

**오류 안내**

| 상황 | 안내 문구 |
|---|---|
| 일시 형식이 틀림 | "일시는 2026-09-22 14:00처럼 적어 주세요. 모르면 비워 두세요." |
| 근거 형식이 틀림 | "근거는 12:34 또는 1:02:03처럼 적어 주세요." |
| 근거가 녹음 길이를 넘음 | "녹음 길이(58:10)보다 뒤의 위치입니다." |

오류가 있으면 적용하지 않고 해당 칸을 빨간 테두리로 표시합니다.

**직접 확인할 기준**
- [ ] 할 일 기한을 "10월 10일"로 고치고 보내면 메일 본문과 첨부 파일에 "10월 10일 (수정됨)"이 있다.
- [ ] 담당자를 비우고 적용하면 `미정`으로 표시된다.
- [ ] 결정사항을 모두 지우면 `없음`으로 표시된다.
- [ ] 근거에 `99:99`처럼 틀린 값을 넣으면 적용되지 않는다.
- [ ] 고치는 중에는 「메일 보내기」를 누를 수 없다.
- [ ] 전체 스크립트에는 「고치기」가 없다.

### F9. `.md` 내려받기

**시작 조건·입력**
- 확인 화면, 보낸 결과 화면, 발송 결과 화면에서 「.md 내려받기」를 누릅니다. 횟수 제한은 없습니다.

**프로그램 동작**
- 지금 화면에 보이는 회의록(적용한 수정 포함, 고치는 중인 내용 제외)으로 `.md` 파일을 만듭니다.
- 파일 이름: `회의록_YYYY-MM-DD.md`
  - 날짜는 회의 일시의 날짜입니다.
  - 일시가 `미정`이면 녹음을 올린 날짜를 씁니다.
  - 같은 날짜의 파일이 이미 내려받아져 있어도 서비스에서 이름을 바꾸지 않습니다. 겹치는 이름은 사용자 기기의 기본 동작(예: 이름 뒤에 `(1)`)에 맡깁니다.

**화면·파일·메일 결과**
- **파일 내용:** PRD 5-1 양식 전체입니다. 제목, 일시, 참석자, 요약, 결정사항, 할 일, 전체 스크립트, AI 작성 안내 순입니다.
- 메일에 첨부하는 파일과 내용이 같습니다. 보낸 뒤에 내려받으면 보낸 첨부 파일과 똑같습니다.
- **화면:** 아래쪽에 알림이 뜹니다. "회의록_2026-09-22.md 내려받기 · 전체 스크립트까지 담긴 파일입니다." 알림은 닫기(×)로 닫습니다.

**오류 안내**
- 24시간이 지나 삭제됨: F7과 같은 문구

**직접 확인할 기준**
- [ ] 일시가 2026-09-22이면 파일 이름이 `회의록_2026-09-22.md`이다.
- [ ] 일시가 `미정`이면 파일 이름에 올린 날짜가 들어간다.
- [ ] 내려받은 파일과 메일 첨부 파일의 내용이 같다.
- [ ] 파일에 전체 스크립트가 들어 있다.

### F10. 메일 보내기

#### 방식 A. 검토 후 보내기

**순서**
1. 확인 화면에서 「메일 보내기」를 누릅니다. 고치는 중이면 눌리지 않습니다.
2. 발송 확인 창 "이 내용으로 메일을 보낼까요?"가 열립니다. 받는 사람, 메일 제목, 본문 구성, 첨부 파일 이름을 보여 주고 "화면에서 고친 내용이 메일 본문과 첨부 파일에 그대로 들어갑니다."라고 안내합니다.
3. 「취소」 또는 닫기(×)를 누르면 확인 화면으로 돌아갑니다.
4. 「보내기」를 누르면 버튼이 "보내는 중"으로 바뀌어 막히고 발송을 시작합니다.
5. Gmail이 메일을 접수하면 곧바로 보낸 결과 화면으로 넘어갑니다. 주소마다 "확인 중"이 표시되고, 최대 2분 안에 "보냄" 또는 "보내지 못함(이유)"으로 바뀝니다.
6. Gmail이 접수 자체를 거절하면 결과 화면으로 넘어가지 않고 확인 화면에 머무릅니다(아래 "발송 결과" 참고).

**받는 주소 처리**
- 올릴 때 입력한 주소 그대로 보냅니다. 확인 화면에서는 바꿀 수 없습니다.

#### 방식 B. 바로 보내기

**순서**
1. 올리기 화면에서 「올리고 바로 보내기」를 누릅니다. 파일과 주소 검사를 통과해야 합니다.
2. 주소 확인 창 "올리기 전에 받는 주소를 확인하세요"가 열립니다. 받는 사람 N명의 주소, 녹음 파일, 메일 구성을 보여 줍니다.
3. 「주소 고치기」 또는 닫기(×)를 누르면 올리기 화면으로 돌아갑니다. 입력값은 그대로입니다.
4. 「이 주소로 올리고 보내기」를 누르면 버튼이 막히고 올리기를 시작합니다.
5. 회의록이 만들어지면 사람의 검토 없이 곧바로 보냅니다.
6. Gmail이 메일을 접수하면 곧바로 발송 결과 화면으로 넘어갑니다. 주소마다 "확인 중"이 표시되고, 최대 2분 안에 "보냄" 또는 "보내지 못함(이유)"으로 바뀝니다.

**받는 주소 처리**
- 주소 확인 창에서 확인한 주소 그대로 보냅니다. 올리기를 시작한 뒤에는 바꿀 수 없습니다.

#### 두 방식 공통

**메일 구성** (PRD 5-4)
- **보내는 사람:** 표시 이름은 "회의록 봇"이고, 이 서비스 전용으로 만든 Gmail 주소로 보냅니다. 답장을 막을 수는 없고, 답장은 이 전용 Gmail의 받은편지함에 쌓입니다.
- **받는 사람:** 입력한 주소 전부를 "받는 사람"으로 넣습니다.
- **제목:** `[회의록] {회의 제목} ({YYYY-MM-DD})`
  - 일시가 `미정`이면 날짜 자리에 `미정`을 적습니다. 예: `[회의록] 신규 기능 출시 일정 회의 (미정)`
- **본문:** 제목, 일시, 참석자, 요약, 결정사항(근거 포함), 할 일(담당자·기한·근거 포함), AI 작성 안내 순입니다.
  - 전체 스크립트는 넣지 않습니다.
  - `미정`, `없음`, `근거 없음`, `(수정됨)`을 그대로 적습니다.
- **첨부:** `회의록_YYYY-MM-DD.md` 1개. 화면에서 내려받는 파일과 같습니다.

**발송 결과**

| 결과 | 화면 표시 | 다음 행동 |
|---|---|---|
| 접수 직후 (확인 중) | Gmail이 메일을 접수하면 곧바로 결과 화면이 열립니다. 주소마다 "확인 중"을 보여 주고, "보낸 뒤 2분이 지나 반송되면 표시되지 않을 수 있습니다."를 함께 안내합니다 | 최대 2분 안에 아래 결과 중 하나로 바뀜 |
| 모두 보냄 | "메일을 보냈습니다"(A) 또는 "검토 없이 바로 보냈습니다"(B), 주소마다 "보냄" | 「.md 내려받기」, 「새 회의록 만들기」 |
| 일부 실패 (모두 반송된 경우 포함) | "N명 중 M명에게 보내지 못했습니다", 실패한 주소마다 "보내지 못함"과 이유. 확인 중이던 주소가 모두 반송되어도 같은 방식으로 보여 줍니다 | 「실패한 주소에 다시 보내기」로 실패한 주소에만 다시 보냄 |
| Gmail이 접수를 거절한 경우 (A) | 결과 화면으로 넘어가지 않고 확인 화면에 머물러 "메일을 보내지 못했습니다. 잠시 뒤 다시 보내 주세요." 고친 내용은 그대로 남습니다 | 「메일 보내기」를 다시 누를 수 있음. 한 통도 나가지 않았으므로 중복 발송이 아님 |
| Gmail이 접수를 거절한 경우 (B) | 발송 결과 화면에서 모든 주소를 "보내지 못함"으로 표시 | 「실패한 주소에 다시 보내기」 |

- **확인 중 → 확정:** 접수 직후에는 주소마다 "확인 중"이 표시됩니다. 이후 최대 2분 동안 반송 여부를 확인해 "보냄" 또는 "보내지 못함"으로 바꿉니다. 2분이 지난 뒤에 온 반송은 화면에 반영되지 않을 수 있습니다.
- **실패 이유:** 받는 쪽에서 주소를 찾을 수 없음, 받는 쪽 메일함이 가득 참, 일시적인 메일 서비스 문제 등을 짧게 적습니다.
- **다시 보내기:** 이미 "보냄"으로 확정된 주소에는 다시 보내지 않습니다(3-4). 누르는 즉시 막히고, 결과에 맞춰 주소별 표시를 새로 바꿉니다.

**오류 안내**
- 위 발송 결과 표와 같습니다.
- 24시간이 지나 삭제됨: F7과 같은 문구

**직접 확인할 기준**
- [ ] 메일을 보낸 직후 결과 화면에서 주소마다 "확인 중"이 보이고, 최대 2분 안에 "보냄" 또는 "보내지 못함"으로 바뀐다.
- [ ] A에서 「보내기」를 빠르게 두 번 눌러도 받는 사람마다 메일이 한 통만 온다.
- [ ] A에서 고친 내용이 메일 본문과 첨부 파일에 그대로 들어 있다.
- [ ] B에서 녹음을 올린 뒤 아무것도 하지 않아도 메일이 온다.
- [ ] B의 주소 확인 창에서 「주소 고치기」를 누르면 아무것도 올라가지 않고 입력값이 남아 있다.
- [ ] 여러 명에게 보낸 메일의 본문에 요약, 결정사항, 할 일이 있고 `.md` 파일이 첨부되어 있으며, 전체 스크립트는 본문에 없다.
- [ ] 없는 주소를 하나 섞어 보내면 그 주소만 "보내지 못함"으로 나오고, 다시 보내도 나머지 사람은 메일을 두 번 받지 않는다.
- [ ] 일시가 `미정`인 회의록의 메일 제목이 `(미정)`으로 끝난다.

### F14. 처음으로 나가기

**시작 조건·입력**
- 올리기 화면, 확인 화면, 결과 화면의 머리글 「처음으로」(모바일은 집 모양 아이콘)를 누릅니다.
- 결과 화면에서는 「새 회의록 만들기」(태블릿·모바일은 「새 회의록」)를 눌러도 됩니다.

**프로그램 동작**
- 올리기 화면에서 아무것도 입력하지 않았으면 묻지 않고 처음 화면으로 갑니다.
- 그 밖에는 나가기 확인 창 "처음 화면으로 갈까요?"를 엽니다.
  - 「머무르기」 또는 닫기(×): 창을 닫습니다.
  - 「처음으로」: 입력값과 회의록을 모두 지우고 처음 화면으로 갑니다. 방식 표시도 사라집니다.
- 처리 중 화면에는 「처음으로」가 없습니다(실패했을 때만 나옴).

**화면·파일·메일 결과**
- 나가기 확인 창의 문구는 어디서 나가는지에 따라 다릅니다.
  - 올리기 화면: "고른 녹음 파일과 입력한 회의 정보, 받는 주소가 모두 지워집니다."
  - 확인 화면: "회의록은 서비스에 보관되지 않습니다. 메일을 보내거나 .md 파일로 내려받지 않고 나가면 이 회의록을 다시 볼 수 없습니다."
  - 결과 화면: "회의록은 서비스에 보관되지 않습니다. 나간 뒤에는 보낸 메일과 내려받은 파일로만 볼 수 있습니다."

**오류 안내**
- 없음.

**직접 확인할 기준**
- [ ] 빈 올리기 화면에서 「처음으로」를 누르면 확인 창 없이 처음 화면으로 간다.
- [ ] 확인 화면에서 나가면 같은 회의록을 다시 열 방법이 없다.

"모두 실패"는 Gmail이 접수 자체를 거절했을 때만 해당하고, 모두 반송된 경우는 일부 실패처럼 다시 보내기를 보여 줍니다. 보내는 사람은 이 서비스 전용 Gmail 주소이고, 결과 화면에 2분 반송 안내를, 처음 화면에 Gemini 처리 안내를 넣습니다. 30일이 지난 메일은 Gmail 필터가 아니라 매일 도는 청소가 IMAP으로 휴지통으로 옮겨 지웁니다 | F7, F10, F11, 3-3 |

**추천안을 정하며 함께 정한 세부 규칙**
- 1시간 이상 녹음의 타임스탬프는 `[h:mm:ss]`로 적습니다.
- 입력한 참석자 이름은 목소리와 연결되지 않아도 참석자 줄에 적습니다.
- 방식 A에서 발송이 모두 실패하면 확인 화면에 머물러 다시 보낼 수 있습니다. 한 통도 나가지 않았으므로 중복 발송이 아닙니다.

### 8-2. 시안에만 있고 실제 서비스에서는 빠지는 것

- 화면 맨 위의 "시안 · 실제 업로드·AI 처리·메일 발송은 일어나지 않습니다" 띠
- 처리 중 화면의 「회의록 확인 화면으로 넘어가기」·「발송 결과 화면으로 넘어가기」 점선 버튼. 실제로는 처리가 끝나면 자동으로 넘어갑니다.
- "시안용 파일 선택 창"과 예시 파일 4개. 실제로는 기기의 파일 선택 창이 열립니다.
- 회의록의 "예시 회의록" 표시, 결과 화면의 "시안 · 실제로 보내지 않음" 표시
- 시안 바깥의 「처음부터 다시」, PC·태블릿·모바일 전환 메뉴

### 8-3. 기기별 차이 (기능은 같고 배치만 다름)

| 항목 | PC | 태블릿 | 모바일 |
|---|---|---|---|
| 파일 고르기 | 끌어다 놓기 + 누르기, 「다른 파일」 | PC와 같음 | 누르기만, 「다른 파일」 없음 (빼고 다시 고름) |
| 올리기 버튼 | 오른쪽 "보내기 전 확인" 패널 | 아래 고정 막대 + 받는 사람 수 | 태블릿과 같음 |
| 메일 정보·결과 화면 버튼 | 오른쪽 패널 | 회의록 위 상자 + 아래 고정 막대 | 태블릿과 같음 |
| 할 일 보기 | 표 | 표 | 카드 |
| 확인 창 | 가운데 창 | 가운데 창 | 아래에서 올라오는 창 |
| 「처음으로」 | 글자 버튼 | 글자 버튼 | 집 모양 아이콘 |
