**구현하며 정한 점과 고친 점**

- 제목 200자, 참석자 이름 50자·50명의 상한은 FRD에 없는 값으로, 서버 검사용으로 정했습니다. 화면 입력칸에도 같은 글자 수 제한을 걸었습니다.
- 파일 선택 창은 mp3·m4a·wav와 소리 파일을 먼저 보여 줍니다. 다른 형식은 끌어다 놓거나, 파일 선택 창의 종류를 "모든 파일"로 바꾸면 고를 수 있고, 고르면 형식 오류가 나옵니다.
- 실제 올리기는 EPIC 3에서 연결합니다. 지금은 검사를 통과하면 A는 "입력 확인을 마쳤습니다" 알림, B는 주소 확인 창이 열리고 「이 주소로 올리고 보내기」를 누르면 같은 알림이 뜹니다.

### 4. EPIC 2 완료 판단

| 개발계획 완료 기준 | 상태 |
|---|---|
| FRD F1~F4 "직접 확인할 기준" 가운데 올리기 전 항목이 모두 통과한다 | 자동 검사·개발 쪽 확인·사용자 확인 통과. F1의 200MB·2시간 초과는 자동 검사와 개발 쪽 확인(실제 파일)으로 확인했고, 사용자 확인 목록에는 없는 항목 |
| F14의 올리기 화면 부분이 통과한다 | 자동 검사·개발 쪽 확인·사용자 확인(행동 7) 통과 |

- 판단: **완료 (2026-09-27).** 필수 자동 검사(`npm run check`)가 모두 통과했고, 사용자 확인 9개 항목(행동 1~8과 R1)이 모두 문제없이 통과했습니다. 시안에 없던 모양에 대한 수정 요청은 없었습니다.
- F1~F4 가운데 회의록이 만들어진 뒤에 확인하는 항목(세 칸을 비워도 회의록이 만들어짐, 제목이 메일 제목과 같음, 일시 `미정` 등)은 EPIC 3 이후에 확인합니다.
- 남은 미확인:
  - 태블릿 실기기 화면. 사용자 확인 목록에 없는 항목이며, 흐름 시험과 개발 쪽 확인(834 폭)으로 대신했습니다.
  - 파일에 담긴 녹음 시각 읽기는 단위 시험으로만 확인했습니다. 화면에 쓰이는 것은 EPIC 5(일시가 비었을 때)입니다.
  - 휴대폰 녹음 앱으로 만든 파일의 길이 읽기는 따로 확인하지 않았습니다. 길이를 읽지 못하면 처리 중에 검사합니다(FRD F1).
