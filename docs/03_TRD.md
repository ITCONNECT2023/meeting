## 1. 사용할 기술과 선택 이유

| 역할 | 기술 | 선택 이유 |
|---|---|---|
| 화면 + 서버 | **Next.js**(App Router) + **TypeScript** | 화면과 서버 기능을 한 프로젝트에 담고, Vercel에 그대로 배포됩니다. TypeScript는 데이터 모양을 미리 정해 두어 실수를 줄입니다 |
| 화면 꾸밈 | CSS Modules + 색·글꼴 변수 | 시안의 색(배경 `#F4F2EC`, 글자 `#1C1B18`, 방식 A 파랑 `#26489A`, 방식 B 주황 `#B84E17`, 오류 빨강 `#B3261E`, 성공 초록 `#2F6B43`)과 글꼴(IBM Plex Sans KR·Mono)을 변수로 옮깁니다. 화면 폭 기준은 모바일 ~599px(시안 390), 태블릿 600~1199px(시안 834), PC 1200px~(시안 1440)입니다 |
| 녹음 임시 보관 | **Vercel Blob**(비공개 저장소) | 브라우저가 200MB 파일을 서버를 거치지 않고 바로 올릴 수 있습니다(서버 함수는 4.5MB 제한) |
| 백그라운드 처리 | **Vercel Workflow** | 창을 닫아도 서버에서 끝까지 진행합니다. 단계마다 진행 상황을 저장해 실패한 단계부터 다시 시도합니다. 단계 하나는 5분(Hobby 함수 한도) 안에 끝나게 나눕니다 |
| 임시 데이터 | **Upstash Redis**(Vercel 연동, 무료 등급) | 정한 시간이 지나면 스스로 지워집니다. 회의록 24시간, 암호 잠금 10분을 저장소가 보장합니다 |
| 받아쓰기·회의록 | **Gemini 3.8 Flash**(유료 등급, `@google/genai`) | T1·T2. 유료 등급은 올린 내용을 학습에 쓰지 않습니다. 결과를 정해진 JSON 모양으로 받아 서버가 검사합니다 |
| 메일 보내기 | Gmail SMTP(`nodemailer`) | T4. 앱 비밀번호로 보내며 비용이 없습니다 |
| 반송 확인 | Gmail IMAP(`imapflow`, `mailparser`) | T5. 같은 앱 비밀번호로 실패 알림만 읽습니다 |
| 녹음 정보 읽기 | `music-metadata`(브라우저) | 올리기 전에 길이(2시간 제한)와 파일에 담긴 녹음 시각(일시가 비었을 때 사용)을 읽습니다 |
| 입력 검사 | `zod` | 같은 검사 규칙을 브라우저와 서버에서 함께 씁니다 |
| 시험 | Vitest(기능 단위), Playwright(화면 흐름) | 5·8장 확인 기준을 자동으로 돌립니다 |

## 2. 처리 순서

### ① 접속 (F13)
1. 암호를 서버가 환경 변수 `ACCESS_PASSWORD`와 비교합니다.
2. 맞으면 30일짜리 서명된 쿠키를 발급합니다. 쿠키에는 "암호 버전"이 들어 있어, 암호를 바꾸면 모든 기기에서 다시 묻습니다.
3. 틀리면 접속 주소(IP)별로 횟수를 셉니다. 5번이면 10분 동안 막습니다.
4. `middleware.ts`가 모든 화면과 API 앞에서 쿠키를 확인합니다.

### ② 올리기 (F1~F4)
1. 브라우저가 형식, 크기, 길이, 주소를 먼저 검사합니다.
2. `POST /api/jobs`로 작업을 만듭니다. 서버가 같은 규칙으로 다시 검사하고 작업 번호(추측할 수 없는 무작위 값)를 돌려줍니다.
3. 브라우저가 Blob으로 직접 올립니다. 이때 서버가 암호 쿠키와 작업 번호를 확인한 뒤에만 올리기 허가를 내주고, 형식은 mp3·m4a·wav로, 크기는 200MB로 제한합니다.
4. 올리기가 끝나면 Blob이 서버에 완료를 알리고, 서버가 Workflow를 시작합니다. 브라우저의 시작 요청은 예비용입니다. 같은 작업은 한 번만 시작되게 막습니다. 그래서 방식 B는 올리기가 끝난 뒤 창을 닫아도 계속 진행됩니다.

### ③ 처리 Workflow
단계 사이에는 작업 번호만 넘기고, 내용은 Redis에 둡니다. Workflow 진행 기록에 회의 내용이 남지 않게 하기 위해서입니다.

| 단계 | 하는 일 | 화면 단계 |
|---|---|---|
| a | Blob 녹음을 Gemini 파일 저장소로 옮깁니다. **옮기면 바로 Blob 원본을 삭제**합니다. 파일을 읽지 못하면 "손상" 오류입니다 | 녹음 파일 올리기 |
| b | **화자 목록 파악:** 녹음 전체를 듣고 목소리마다 `화자N`을 매깁니다. 입력한 참석자 이름과 녹음 속 호칭이 확실히 맞을 때만 이름을 연결합니다 | 스크립트 만들기 |
| c | **구간 받아쓰기:** 20분 구간으로 나눠 동시에 요청합니다. 각 요청에 b의 화자 목록을 넘겨 번호를 맞춥니다. 발언마다 `{시작 시각, 화자, 내용}`을 받고, 숫자는 아라비아 숫자로 적게 합니다 | 〃 |
| d | **서버 검사:** 시각이 구간 안인지, 앞으로만 흐르는지, 녹음 길이 이내인지 확인합니다. 틀린 구간만 최대 2번 다시 요청합니다. 발언이 하나도 없으면 "말소리 없음" 오류입니다 | 〃 |
| e | **Gemini 녹음 파일 삭제**(성공·실패와 관계없이 항상), 개인정보 번호 가림 | 〃 |
| f | **회의록 쓰기:** 스크립트를 줄 번호와 함께 넘깁니다(`L0012 [03:15] 이지은: …`). 요약, 결정사항, 할 일과 **근거 줄 번호**를 JSON으로 받습니다. 서버가 줄 번호를 실제 시각으로 바꿉니다. 없는 줄 번호를 가리키면 다시 요청합니다. 확인되지 않은 담당자·기한은 `미정`, 항목이 없으면 `없음`으로 채웁니다. 회의록에도 가림을 한 번 더 적용합니다 | 회의록 만들기 |
| g | 회의록을 Redis에 저장합니다(24시간 뒤 자동 삭제). A는 확인 화면으로, B는 ④ 발송으로 넘어갑니다 | - |

- 브라우저는 `GET /api/jobs/{id}`를 2초마다 불러 단계 상태를 표시합니다.
- 일시는 입력값 → 파일에 담긴 녹음 시각 → `미정` 순으로 정합니다. 참석자 줄은 입력한 이름 먼저, 그다음 `화자N`입니다.
- 근거 시각은 AI가 직접 쓰지 않고 서버가 줄 번호에서 바꿔 적습니다. 그래서 "타임스탬프 위치에 실제 발언이 있다"(PRD 완료 기준 4)가 구조적으로 지켜집니다.

### ④ 발송 Workflow (F10)
1. 보내기 요청마다 잠금을 걸어 한 번만 처리합니다.
2. 아직 "보냄"이 아닌 주소를 모두 "받는 사람"에 넣어 한 통으로 보냅니다. 메일마다 고유 번호(Message-ID)를 붙입니다.
3. 15초마다 전용 받은편지함에서 보낸 메일에 대한 실패 알림을 찾습니다. 최대 2분까지 찾습니다.
4. 알림이 온 주소는 "보내지 못함(이유)", 나머지는 "보냄"으로 확정합니다.
5. 이유는 실패 알림의 상태 코드로 정합니다. `5.1.1` 주소를 찾을 수 없음, `5.2.2` 메일함이 가득 참, `4.x.x` 일시적인 메일 서비스 문제, 그 밖은 받는 쪽에서 거절함입니다.
6. Gmail이 접수 자체를 거절하면 모두 실패로 처리합니다. A는 확인 화면에 머무릅니다.
7. **중복 방지:** 발송 도중 서버가 끊겨 다시 시도할 때는, 먼저 Gmail "보낸편지함"에 같은 고유 번호가 있는지 확인합니다. 있으면 다시 보내지 않습니다.

### ⑤ 편집·내려받기·나가기 (F8, F9, F14)
- **「적용」:** `PATCH /api/jobs/{id}/minutes`로 보냅니다. 서버가 형식과 녹음 길이를 검사하고, `(수정됨)`을 붙이고, 가림을 다시 적용한 뒤 저장합니다. 화면, 파일, 메일이 모두 서버의 한 벌에서 나옵니다.
- **「.md 내려받기」:** `GET /api/jobs/{id}/download`. 메일 첨부와 같은 코드(`render-md`)로 만듭니다.
- **나가기:** 「처음으로」, 「새 회의록」, 창 닫기, 새로고침이면 서버에 삭제를 알립니다(창 닫기는 `sendBeacon`).
  - A는 처리 중이면 Workflow를 멈추고 모두 지웁니다.
  - B는 올리기가 끝났으면 "나감" 표시만 하고 끝까지 보냅니다. 발송이 끝나면 즉시 지웁니다.
- 작업 번호는 브라우저 메모리에만 둡니다. 그래서 새로고침하면 처음 화면이 열립니다. 결과 화면으로 넘어갈 때 방문 기록을 바꿔 뒤로 가기로 확인 화면에 돌아가지 않게 합니다.
- **「다시 시도」:** 메모리에 남은 같은 파일과 입력값으로 새 작업을 만듭니다.

### 걸리는 시간과 비용
목표치이며, 8장 시험에서 실제로 잽니다.

| 녹음 길이 | 처리 시간(올리기 제외) | Gemini 비용 |
|---|---|---|
| 1시간 | 약 3~5분 | 약 700원 |
| 2시간 | 약 5~8분 | 약 1,800원 |

- 녹음을 여러 번 나눠 요청하면 매번 녹음 전체를 다시 읽으므로, 길이가 두 배면 비용은 두 배보다 조금 더 듭니다.
- 한 달에 1시간 회의 20건이면 약 1만 4천 원입니다. Gemini 3.8 Flash 요금이 2027년 1월부터 두 배로 오를 예정이라 이후 약 2만 8천 원입니다.
- Gmail, Vercel Hobby, Blob, Redis는 무료 한도 안에서 씁니다.

## 4. 데이터 저장·이동·복구

### 가져오기와 내보내기
- 들어오는 데이터는 녹음 파일(F1)과 입력값뿐입니다.
- 나가는 데이터는 `.md` 내려받기(F9)와 메일(F10)뿐입니다.
- 서비스 안에 가져오기, 목록, 검색은 없습니다.

### 어디에 얼마나 남는가

| 데이터 | 위치 | 남는 시간 |
|---|---|---|
| 녹음 원본 | Vercel Blob | Gemini로 옮기는 즉시 삭제 (보통 1분 이내) |
| 녹음 사본 | Gemini 파일 저장소 | 받아쓰기가 끝나거나 실패하는 즉시 삭제. 놓쳐도 Gemini가 48시간 뒤 자동 삭제 |
| 작업·스크립트·회의록·발송 상태 | Upstash Redis | 결과 화면을 나가면 즉시 삭제, 늦어도 24시간 뒤 자동 삭제 |
| 암호 틀린 횟수 | Upstash Redis | 10분 |
| Workflow 진행 기록 | Vercel | 작업 번호와 단계 상태만 담음. 실행이 끝나고 1일 뒤 삭제 |
| 보낸 메일·반송 알림 | 전용 Gmail | 계정에 남음. 30일이 지난 메일은 매일 도는 청소가 IMAP으로 Gmail의 휴지통으로 옮겨 지웁니다. Gmail 필터는 메일이 며칠 지났는지로 고를 수 없어, 필터 대신 이 방법을 씁니다(EPIC 9-1) |

### 백업
- 회의 데이터는 **일부러 백업하지 않습니다**(F11). 기록은 보낸 메일과 내려받은 파일로만 남습니다.
- 코드는 GitHub에 둡니다.
- 설정값(환경 변수) 목록은 `.env.example`에 이름만 적고, 실제 값은 Vercel에만 둡니다.

### 복구
- **처리 중 서버가 끊기면:** Workflow가 끊긴 단계부터 자동으로 이어 갑니다. 외부 서비스 오류는 단계별로 최대 3번 간격을 늘려 가며 다시 시도합니다.
- **잘못 배포하면:** Vercel에서 직전 배포로 되돌립니다(Instant Rollback).
- **서비스를 통째로 다시 만들어야 하면:** GitHub 저장소를 Vercel에 연결하고, Blob과 Redis를 새로 만든 뒤, 환경 변수를 다시 넣으면 됩니다. 옮길 회의 데이터는 없습니다.
- **남은 녹음 청소:** 하루 1번 Blob과 Gemini 파일 저장소에서 1시간이 지난 녹음을 찾아 지웁니다.

## 5. 정보 보호

- **접속:** 팀 공용 암호입니다. 쿠키는 브라우저 스크립트가 읽을 수 없고(`HttpOnly`) 보안 연결로만 오갑니다(`Secure`). 30일 유지, 5번 틀리면 10분 잠금입니다.
- **작업 번호:** 추측할 수 없는 무작위 값입니다. 모든 API가 쿠키와 작업 번호를 함께 확인합니다.
- **녹음 저장소:** Blob은 비공개 저장소입니다. 주소를 알아도 열리지 않습니다.
- **외부로 가는 데이터**
  - 녹음과 스크립트는 Google Gemini(유료 등급, 학습에 쓰지 않음, 해외에서 처리)로만 갑니다.
  - 회의록은 입력한 받는 주소로만 갑니다.
- **개인정보 가림 (F12):** 주민등록번호, 휴대전화·일반전화, 카드번호, 계좌번호 4종을 `***`로 바꿉니다.
  - 계좌번호는 "하이픈으로 이어진 10~14자리 숫자"를 기준으로 하고, 날짜·시각 모양은 제외합니다.
  - 받아쓰기 때 숫자를 아라비아 숫자로 적게 해 가려지는 범위를 넓힙니다.
  - 가림은 스크립트 저장 전, 회의록 저장 전, 「적용」할 때마다 서버에서 합니다.
- **비밀값:** Gemini 키, Gmail 앱 비밀번호, 접속 암호, 쿠키 서명 키는 Vercel 환경 변수에만 둡니다. 코드와 GitHub에는 넣지 않습니다.
- **전용 Gmail:** 2단계 인증을 켜고, 앱 비밀번호는 이 서비스용 하나만 만듭니다. 반송 확인은 실패 알림을 보내는 주소(mailer-daemon)에서 온 메일만 엽니다.
- **기록(로그):** 작업 번호, 단계, 오류 코드, 걸린 시간, 사용한 AI 토큰 수만 남깁니다. 녹음 내용, 스크립트, 이름, 메일 주소는 남기지 않습니다. Hobby의 실행 기록은 1시간 뒤 사라집니다.

## 6. 오류 대응

| 오류 코드 | 언제 | 처리 | 화면 문구 |
|---|---|---|---|
| `AUTH_WRONG` / `AUTH_LOCKED` | 암호 틀림 / 5번 틀림 | 횟수 세기 / 10분 막기 | FRD 6장 문구 그대로 |
| `FILE_TYPE` / `FILE_TOO_LARGE` / `TOO_LONG` | 형식·크기·길이 | 브라우저에서 먼저 막고, 서버와 Blob 허가 단계에서 한 번 더 막음 | 〃 |
| `UPLOAD_FAILED` | 올리는 중 연결 끊김 | Blob이 자동으로 다시 시도한 뒤에도 실패하면 중단 | 〃 (「다시 시도」) |
| `FILE_CORRUPT` / `NO_SPEECH` | Gemini가 파일을 못 읽음 / 발언 0개 | 녹음 삭제 후 중단 | 〃 (「처음으로」) |
| `TRANSCRIBE_FAILED` / `MINUTES_FAILED` | AI 오류(한도 초과, 서버 오류), 결과 검사 실패 | 간격을 늘려 최대 3번 다시 요청, 그래도 안 되면 중단. B는 메일을 보내지 않음 | 〃 (「다시 시도」) |
| `MAIL_ALL_FAILED` | Gmail 접속 실패, 하루 한도(약 500명) 초과 | A는 확인 화면에 머묾, B는 모든 주소 "보내지 못함" | 〃 |
| `MAIL_PARTIAL` | 반송된 주소 있음 | 주소별 표시, 실패한 주소만 다시 보내기 | 〃 |
| `EDIT_INVALID` | 일시·근거 형식 틀림, 녹음 길이 초과 | 적용하지 않고 해당 칸 표시 | 〃 |
| `EXPIRED` | 24시간 지남 또는 이미 지움 | 서버가 "없어짐"(410)으로 응답 | "보관 시간(24시간)이 지나…" |

- 브라우저는 서버의 오류 코드만 받아 FRD 6장 문구로 바꿔 보여 줍니다. 외부 서비스의 원래 오류 내용은 화면에 내보내지 않습니다.

## 7. 배포 방법

1. **GitHub:** 개인 계정에 비공개 저장소를 만듭니다. Hobby는 조직 저장소를 자동 배포하지 못합니다.
2. **Vercel:** 저장소를 연결합니다. `main`에 합치면 실제 서비스로 배포되고, 다른 가지(branch)는 시험용 미리보기 주소로 배포됩니다. 함수 지역은 서울(icn1)입니다.
3. **저장소 연결:** Vercel 화면에서 Blob(비공개)과 Upstash Redis를 만들어 연결합니다. 접속 정보는 자동으로 환경 변수에 들어갑니다.
4. **환경 변수:** `ACCESS_PASSWORD`, `SESSION_SECRET`, `GEMINI_API_KEY`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `MAIL_FROM_NAME=회의록 봇`, `CRON_SECRET`, `MAIL_ALLOWLIST`(미리보기에서만 사용. 여기 적은 시험 주소로만 메일이 나감)
5. **자동 검사:** GitHub에 올릴 때마다 GitHub Actions가 형식 검사, 타입 검사, 단위 시험을 돌립니다. 통과해야 `main`에 합칩니다.
6. **청소 예약:** `vercel.json`에 하루 1번 청소 예약(cron)을 등록합니다.

### 배포 전 준비와 알려진 위험
- 전용 Gmail 계정을 만들고 2단계 인증과 앱 비밀번호를 발급합니다. Gemini API는 결제를 연결합니다.
- **Hobby 약관:** Hobby는 개인·비상업 용도만 허용합니다. 팀 업무용 사용은 약관 위반 소지가 있습니다(T6에서 인지하고 유지).
- **Hobby 한도:** 사용량 한도를 넘으면 서비스가 멈춥니다. Workflow는 월 5만 이벤트까지이고, 회의 1건에 약 50~100 이벤트를 씁니다.
- **Gmail 차단 위험:** 해외 서버(Vercel)에서 Gmail로 로그인하면 Google이 의심 로그인으로 막을 수 있습니다. 배포 직후 실제 발송으로 확인합니다.

## 8. 확인 방법

### 1) 단위 시험 (Vitest, 자동)
- 가림 4종: 걸려야 할 예시와 걸리면 안 되는 예시(날짜, 금액)
- 파일 이름 규칙, 타임스탬프 읽기·쓰기(`99:99` 거절 등)
- `.md` 결과가 PRD 5-1 예시와 글자 단위로 같은지
- 메일 제목·본문(`(미정)`, 전체 스크립트 제외)
- 편집 규칙(비우면 `미정`/`없음`/`근거 없음`, `(수정됨)`)
- 줄 번호 → 시각 변환, 받아쓰기 결과 검사
- 반송 알림 해석(실제 반송 메일 표본)

### 2) 흐름 시험 (Playwright, 자동)
- AI와 메일을 가짜로 바꿔 끼우고(교체 창구 활용) FRD 4장의 "직접 확인할 기준"을 화면에서 돌립니다.
- 칩 입력, 탭을 바꿔도 입력값 유지, 보내기 연타, 뒤로 가기, 새로고침, 고치는 중 발송 막힘
- PC·태블릿·모바일 폭 3가지

### 3) 실제 시험 (사람, 배포 전 미리보기 주소에서)

| PRD 완료 기준 | 시험 |
|---|---|
| 1 | mp3, m4a, wav 각 1건으로 회의록 만들기 |
| 3 | 기한을 말하지 않은 할 일이 담긴 녹음 → 기한이 `미정` |
| 4 | 결정사항·할 일의 시각을 스크립트에서 찾아 실제 발언 확인 |
| 5 | 3명 녹음에 2명 이름만 입력 → 나머지 1명은 `화자N` |
| 6·8 | 고친 내용이 메일 본문과 첨부에 들어갔는지, 여러 명에게 보냈을 때 본문·첨부 확인 |
| 7 | B에서 올리기 후 창 닫기 → 정확히 1통 도착 |
| 10 | 처리 후 Blob과 Gemini 파일 목록에 녹음이 0건 |
| 11 | 실제 팀 회의 3건에서 결정사항·할 일이 녹음과 어긋나지 않음 |

- 추가 시험: 오타 주소 1개를 섞어 그 주소만 "보내지 못함"이 되는지, 전화번호를 말한 녹음이 `***`로 나오는지
- 속도와 비용: 10분, 1시간, 2시간 녹음으로 단계별 시간과 Gemini 토큰 수를 기록해 2장의 목표치와 비교합니다. 넘으면 구간 길이(20분)나 요청 방식을 조정합니다.
