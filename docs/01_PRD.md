# 회의록 자동 작성 서비스 PRD (MVP)

- 작성일: 2026-09-26
- 상태: 확정
- 범위: MVP(처음에 핵심 기능만 담아 빠르게 검증하는 버전)

## 1. 사용 목적

**해결할 문제**
- 회의가 끝난 뒤 회의록을 정리하는 데 시간이 걸립니다.
- 기억에 의존해 정리하다 보니 결정사항이나 할 일이 빠지거나 다르게 적힙니다.

**목적**
- 회의 녹음 파일을 올리면 AI가 **녹음에 근거한 회의록**을 만듭니다.
- 만든 회의록은 화면에서 보고, 파일로 내려받고, 팀원에게 메일로 보낼 수 있습니다.

**핵심 원칙: 녹음에 근거한다**
- 녹음에서 확인되지 않는 내용은 지어내지 않고 **"미정"**으로 표시합니다.
- 결정사항과 할 일에는 **타임스탬프**(녹음 안의 위치, 예: `[12:34]`)를 붙여 원래 발언을 확인할 수 있게 합니다.
- 전체 스크립트(녹음을 글로 옮긴 내용)는 수정하지 않은 원본으로 유지합니다.

## 2. 사용자와 사용 순서

**사용자**
- 우리 팀 내부에서 서로 아는 소수가 씁니다.
- **올리는 사람:** 회의를 주관하거나 정리하는 팀원입니다.
- **받는 사람:** 회의록을 메일로 받는 팀원입니다.

**방식 A. 검토 후 보내기**
1. 녹음 파일을 올립니다.
2. 제목, 일시, 참석자 이름을 입력합니다. 모두 선택 사항입니다.
3. 받는 메일 주소를 입력합니다.
4. AI가 회의록을 만듭니다.
5. 화면에서 회의록을 확인하고 필요하면 고칩니다. 전체 스크립트는 고칠 수 없습니다.
6. 메일로 보내고, 필요하면 `.md` 파일로 내려받습니다.

**방식 B. 바로 보내기**
1. 녹음 파일을 올리고 받는 메일 주소를 입력합니다. 제목, 일시, 참석자는 선택 입력입니다.
2. AI가 회의록을 만든 뒤, 사람의 검토 없이 곧바로 메일을 보냅니다.
3. 보낸 결과를 화면에서 보고 `.md` 파일로 내려받을 수 있습니다.

## 3. 필수 기능

| 번호 | 기능 | 내용 |
|---|---|---|
| F1 | 녹음 파일 올리기 | mp3, m4a, wav 형식을 지원합니다 |
| F2 | 회의 정보 선택 입력 | 제목, 일시, 참석자 이름을 입력할 수 있고 모두 비워도 됩니다 |
| F3 | 받는 메일 주소 입력 | 여러 명에게 보낼 수 있습니다 |
| F4 | 보내기 방식 선택 | "검토 후 보내기"와 "바로 보내기" 중에서 고릅니다 |
| F5 | 스크립트 만들기 | 녹음을 글로 옮깁니다(음성 인식). 목소리로 말한 사람을 나누고(화자 분리), 발언마다 타임스탬프를 붙입니다 |
| F6 | 회의록 만들기 | 5장의 양식과 작성 규칙에 따라 만듭니다 |
| F7 | 결과 화면 보기 | 두 방식 모두 만들어진 회의록을 화면에서 볼 수 있습니다 |
| F8 | 검토 중 편집 | 검토 방식에서는 제목부터 할 일까지 고칠 수 있습니다. 전체 스크립트는 보기만 가능합니다 |
| F9 | `.md` 내려받기 | 파일 이름은 `회의록_YYYY-MM-DD.md` 규칙을 따릅니다(5장 참고) |
| F10 | 메일 보내기 | 본문에는 요약, 결정사항, 할 일을 넣고, 전체 회의록은 `.md` 파일로 첨부합니다 |
| F11 | 보관하지 않음 | 녹음 파일은 처리가 끝나면 삭제합니다. 회의록도 서비스에 쌓아 두지 않습니다 |

## 4. 제외 기능 (MVP 이후 검토)

| 제외 기능 | 제외 이유 |
|---|---|
| 회원가입, 로그인, 팀별 권한 | 우리 팀 내부용이라 필요하지 않습니다 |
| 요금 결제 | 내부용이라 필요하지 않습니다 |
| 회의록 보관, 목록, 검색 | 기록은 메일과 `.md` 파일로 남습니다 |
| 녹음 보관, 타임스탬프를 눌러 다시 듣기 | 보안 부담이 크고 저장 공간이 필요합니다 |
| 전체 스크립트 편집 | 근거로서의 원본을 유지해야 합니다 |
| 결과 화면에서 "화자1=김민수" 직접 짝짓기 | 올릴 때 참석자 이름을 입력하는 방식으로 대체합니다 |
| AI가 빈칸을 추정해서 채우기 | 녹음 근거 원칙에 어긋납니다 |
| 서비스 안에서 바로 녹음하기, 화상회의(Zoom 등) 연동 | MVP 핵심이 아닙니다 |
| Word, PDF 등 다른 형식으로 내려받기 | MVP 핵심이 아닙니다 |
| 할 일을 캘린더나 업무관리 도구에 자동 등록 | MVP 핵심이 아닙니다 |

## 5. 회의록 양식

### 5-1. 회의록 (`.md` 파일, 화면 표시)

```markdown
# 신규 기능 출시 일정 회의

- **일시:** 2026-09-22 14:00
- **참석자:** 김민수, 이지은, 화자3

## 요약
- 신규 기능 출시일을 두고 개발 일정과 QA 기간을 논의했다.
- 마케팅 자료는 출시 1주 전까지 준비하기로 했다.

## 결정사항
1. 출시일을 10월 15일로 확정한다. `[12:34]`
2. QA 기간은 5일로 한다. `[18:02]`

## 할 일
| 할 일 | 담당자 | 기한 | 근거 |
|---|---|---|---|
| 출시 공지 초안 작성 | 이지은 | 10월 8일 | `[21:45]` |
| 보고서 정리 | 김민수 | 미정 | `[23:10]` |
| 테스트 계정 준비 | 미정 | 미정 | `[25:31]` |

## 전체 스크립트
[00:00] 김민수: 시작하겠습니다. 오늘은 출시 일정 얘기부터 하죠.
[00:07] 이지은: 네, 개발 쪽 일정부터 공유드릴게요.
[00:15] 화자3: ...
```

### 5-2. 항목별 작성 규칙

| 항목 | 입력했을 때 | 입력하지 않았을 때 |
|---|---|---|
| 제목 | 입력한 제목을 씁니다 | AI가 녹음 내용을 바탕으로 짓습니다 |
| 일시 | 입력한 일시를 씁니다 | 파일에 담긴 녹음 시각을 씁니다. 그 시각도 없으면 "미정"으로 둡니다 |
| 참석자 | 입력한 이름을 녹음 속 호칭과 연결합니다 | 녹음에서 이름이 확인되면 그 이름을 쓰고, 아니면 "화자1, 화자2"로 둡니다 |
| 요약 | 녹음 내용만으로 작성합니다. 타임스탬프는 붙이지 않습니다 | 같음 |
| 결정사항 | 녹음에서 합의된 것만 적고 타임스탬프를 붙입니다. 없으면 "없음"으로 둡니다 | 같음 |
| 할 일 | 담당자와 기한이 녹음에서 확인되지 않으면 "미정"으로 둡니다. 타임스탬프를 붙이고, 없으면 "없음"으로 둡니다 | 같음 |
| 전체 스크립트 | 발언마다 `[타임스탬프] 이름(또는 화자N): 내용` 형식으로 씁니다. 원본을 그대로 유지합니다 | 같음 |

- 참석자 이름이 확실하지 않으면 추측하지 않고 "화자N"으로 둡니다.
- 검토 방식에서 사람이 고친 내용은 녹음 근거 원칙의 예외로, 검토자 책임으로 봅니다.

### 5-3. 파일 이름 규칙
- `회의록_YYYY-MM-DD.md` 형식이고, 날짜는 **회의 일시**를 기준으로 합니다. 예: `회의록_2026-09-22.md`
- 회의 일시가 "미정"이면 녹음을 올린 날짜를 씁니다.

### 5-4. 메일 구성
- **제목:** `[회의록] {회의 제목} ({날짜})`
- **본문:** 제목, 일시, 참석자, 요약, 결정사항, 할 일을 넣습니다. 전체 스크립트는 넣지 않습니다.
- **첨부:** 전체 회의록 `.md` 파일 1개입니다. 화면에서 내려받는 파일과 같습니다.

## 6. 완료 기준

아래를 모두 만족하면 MVP가 완성된 것으로 봅니다.

1. mp3, m4a, wav 파일로 각각 회의록이 만들어진다.
2. 회의록에 제목, 일시, 참석자, 요약, 결정사항, 할 일, 전체 스크립트가 모두 들어 있다. 비어 있는 항목은 "미정" 또는 "없음"으로 표시된다.
3. 기한을 말하지 않은 할 일이 담긴 시험 녹음에서 기한이 "미정"으로 나온다. AI가 날짜를 지어내지 않는다.
4. 결정사항과 할 일에 모두 타임스탬프가 있고, 스크립트의 그 위치에 실제로 근거가 되는 발언이 있다.
5. 참석자 이름을 입력하면 녹음 속 호칭과 연결된다. 확실하지 않은 사람은 "화자N"으로 남는다.
6. 검토 방식에서 고친 내용이 메일 본문과 첨부 파일에 그대로 반영된다. 전체 스크립트는 고칠 수 없다.
7. 바로 보내기 방식에서 녹음을 올린 뒤 사람이 아무것도 하지 않아도 메일이 발송된다.
8. 여러 명에게 보낸 메일에 요약, 결정사항, 할 일이 본문으로 들어 있고 `.md` 파일이 첨부되어 있다.
9. 내려받은 파일 이름이 5-3 규칙을 따른다.
10. 처리가 끝난 녹음 파일이 서비스에 남아 있지 않다.
11. 실제 팀 회의 녹음 3건으로 시험했을 때, 결정사항과 할 일이 녹음 내용과 어긋나는 경우가 없다.

## 7. 미정 사항

| 번호 | 정할 것 | 예시 |
|---|---|---|
| U1 | 녹음 파일 최대 길이와 크기 | 최대 2시간, 200MB |
| U2 | 지원 언어 | 한국어만 지원할지, 영어가 섞인 회의도 다룰지 |
| U3 | 검토 방식에서 결과를 유지하는 시간 | 24시간 뒤 자동 삭제 |
| U4 | 사람이 고친 부분에 "수정됨" 표시를 할지 | 할 일 기한 옆에 `(수정됨)` 표시 |
| U5 | 회의록 끝에 "AI 작성" 안내 문구를 넣을지 | "이 회의록은 녹음을 바탕으로 AI가 작성했습니다." |
| U6 | 바로 보내기가 실패했을 때 알리는 방법 | 녹음 인식에 실패하면 올린 사람에게 메일로 알림 |
| U7 | 로그인 없이 팀 밖 사람의 사용을 막는 방법 | 팀 공용 접속 암호, 사내망에서만 접속 |
| U8 | 메일 발신자 표시 | "회의록 봇 <no-reply@...>" |
| U9 | 같은 날 회의가 여러 건일 때 파일 이름이 겹치는 문제 | `회의록_2026-09-22_2.md` |
| U10 | 받는 사람 수 제한 | 최대 20명 |
