# 회의록 자동 작성 서비스 개발 계획 (MVP)

- 작성일: 2026-09-26
- 근거 문서: `docs/01_PRD.md`, `docs/02_FRD.md`, `docs/03_TRD.md`, `design/01_PC.html` · `02_Tablet.html` · `03_Mobile.html`
- 상태: 확정 (결정 기록은 0장)
- 개발 계획: PRD·FRD·TRD에서 정한 기능을 어떤 순서로, 얼마만큼씩 만들고, 어떻게 확인할지 적은 문서입니다. 기능과 기술은 앞의 문서를 따르며 이 문서에서 바꾸지 않습니다. 다만 배포 전까지 내 컴퓨터에서 대신 쓰는 도구는 0장 D5에 적었습니다.

### 용어

| 용어 | 뜻 |
|---|---|
| EPIC (작업 묶음) | 끝나면 화면에서 결과를 확인할 수 있는 큰 단위입니다. 모두 10개입니다 |
| 작업 | EPIC 안에서 한 번에 만드는 조각입니다(예: `1-4`). 파일 1~3개 규모로 반나절 안에 끝나며, 끝날 때 자동 시험이 통과해야 합니다. 모두 55개입니다 |
| 로컬 | 내 컴퓨터 안을 말합니다. "로컬에서 실행"은 인터넷에 올리지 않고 내 컴퓨터에서만 서비스를 띄우는 것입니다 |
| 교체 창구 | 같은 역할을 하는 서로 다른 도구를 갈아 끼울 수 있게 만든 연결 부분입니다. 예: 녹음 보관을 지금은 컴퓨터 폴더에, 배포 뒤에는 Vercel Blob에 |
| Docker | 프로그램을 컴퓨터에 직접 설치하지 않고 격리된 상자 안에서 돌리는 도구입니다. 로컬 Redis를 돌리는 데 씁니다 |
| 단위 시험 | 함수 하나가 맞게 동작하는지 자동으로 확인하는 시험입니다(Vitest) |
| 흐름 시험 | 브라우저를 자동으로 조작해 화면 흐름을 확인하는 시험입니다(Playwright) |
| 가짜 AI · 가짜 메일 | 실제 Gemini·Gmail 대신 정해진 예시 결과를 돌려주는 대역입니다. 비용 없이 매번 같은 결과로 시험합니다. TRD의 교체 창구를 씁니다 |
| 회귀 | 새로 만든 기능 때문에 전에 되던 기능이 망가지는 것입니다 |
| 정답표 | 시험 녹음에 실제로 들어 있는 결정사항, 할 일, 담당자, 기한, 대략의 위치를 사람이 적어 둔 표입니다. AI 결과를 이 표와 맞춰 봅니다 |

### 로컬 시험의 한계와 대비

아래는 내 컴퓨터에서는 확인할 수 없고 EPIC 10에서 확인합니다. 로컬에서 할 수 있는 대비를 미리 해 둡니다.

| 배포 환경에서만 드러나는 것 | 로컬에서 하는 대비 | 확인하는 곳 |
|---|---|---|
| Blob 직접 올리기 (서버 함수 4.5MB 한도를 피하는 방식) | 녹음 보관을 교체 창구로 분리해 올리기 흐름의 나머지는 그대로 쓰게 합니다 | 10-3, 10-5 |
| 함수 한 번에 5분 한도 (Hobby) | Workflow 단계마다 걸린 시간을 기록하고, 4분이 넘으면 경고를 남깁니다. 2시간 녹음으로 확인합니다 | 5-6, 10-5 |
| 해외 서버에서 Gmail 로그인이 막힐 위험 | 없음 (로컬은 국내 접속이라 막히지 않음) | 10-5 |
| 보안 연결 전용 쿠키, 서울 지역 함수 | 환경 변수로 켜고 끌 수 있게 만듭니다 | 10-4 |
| Hobby 사용량 한도 (Workflow 월 5만 이벤트) | 회의 1건에 쓰는 이벤트 수를 로컬에서 셉니다 | 5-6, 10-5 |

## 3. 진행 방법과 회귀 막기

### 3-1. 내 컴퓨터에서 서비스를 띄우는 명령

| 명령 | 하는 일 | 언제 |
|---|---|---|
| `npm run dev` | 로컬 Redis(Docker)를 켜고 개발 모드로 띄웁니다. 코드를 고치면 화면이 바로 바뀝니다 | 개발할 때 |
| `npm run local` | 로컬 Redis를 켜고 운영과 같은 방식(빌드 후 실행)으로 띄웁니다 | EPIC을 마치고 화면을 확인할 때 |
| `npm run check` | 형식 검사, 타입 검사, 단위 시험, 흐름 시험(3가지 폭)을 모두 돌립니다 | 작업과 EPIC을 마칠 때 |
| `npm run test:real` | 실제 Gemini로 시험 녹음을 처리해 정답표와 비교합니다 (비용 발생) | EPIC 5부터, EPIC을 마칠 때 |
| `npm run cleanup` | 1시간이 지난 녹음(임시 폴더, Gemini)과 오래된 기록을 지웁니다 | EPIC 9부터 필요할 때 |

- **PC에서 확인:** 브라우저로 `http://localhost:3000`을 엽니다.
- **휴대폰·태블릿에서 확인:** PC와 같은 와이파이에서 `http://192.168.0.18:3000`을 엽니다. PC의 주소가 바뀌면 `npm run local`이 시작할 때 주소를 알려 줍니다. 처음 한 번 Windows 방화벽에서 접속을 허용해야 합니다.

### 3-2. 작업 하나를 진행하는 순서

### EPIC 7. 메일 보내기 — 검토 후 보내기(A)

**만들 기능**
- 7-1 `render-email.ts`:
  - 제목은 `[회의록] {회의 제목} ({YYYY-MM-DD})`이고, 일시가 미정이면 `(미정)`입니다.
  - 본문은 제목, 일시, 참석자, 요약, 결정사항, 할 일, AI 작성 안내 순이고, 스크립트는 넣지 않습니다.
  - 첨부는 `render-md`로 만든 파일입니다.
- 7-2 `lib/mail/smtp.ts`:
  - nodemailer로 "회의록 봇 <전용 Gmail>"에서, 모든 주소를 "받는 사람"으로 보냅니다.
  - 메일마다 고유 번호(Message-ID)를 붙입니다.
  - 가짜 메일 창구를 만듭니다.
  - 로컬에서는 `MAIL_ALLOWLIST`에 적은 주소로만 보냅니다(시험 중 다른 사람에게 잘못 보내는 것을 막음).
- 7-3 `lib/mail/bounce.ts`: IMAP으로 mailer-daemon이 보낸 실패 알림만 읽습니다. 상태 코드로 이유를 정하고(`5.1.1` 주소 없음, `5.2.2` 메일함 가득 참, `4.x.x` 일시적 문제, 그 밖은 받는 쪽 거절), 실제 반송 메일 표본으로 시험합니다.
- 7-4 `workflows/send-mail.ts`:
  - 보내기 요청마다 잠금을 걸어 한 번만 처리하고, 아직 "보냄"이 아닌 주소만 보냅니다.
  - 15초 간격으로 최대 2분 동안 반송을 확인합니다.
  - 중간에 끊겨 다시 시도할 때는 보낸편지함에서 같은 고유 번호를 먼저 확인합니다.
- 7-5 발송 확인 창과 보낸 결과 화면(D3):
  - 「보내기」를 누르면 버튼이 "보내는 중"으로 바뀌어 막힙니다.
  - Gmail이 접수하면 바로 보낸 결과 화면으로 넘어가고, 주소마다 "확인 중"이 2분 안에 "보냄" 또는 "보내지 못함(이유)"으로 바뀝니다.
  - 부분 실패나 전체 반송이면 "N명 중 M명에게 보내지 못했습니다"와 「실패한 주소에 다시 보내기」를 보여 줍니다.
  - "보낸 뒤 2분이 지나 반송되면 표시되지 않을 수 있습니다." 안내를 넣습니다.
  - Gmail이 접수를 거절하면 확인 화면에 머물러 "메일을 보내지 못했습니다. 잠시 뒤 다시 보내 주세요."를 보여 줍니다.
  - 결과 화면으로 넘어갈 때 방문 기록을 바꿔 뒤로 가기를 막고, 결과 화면의 나가기 창 문구를 넣습니다.

**완료 기준**
- FRD F10의 A 기준과 공통 기준이 모두 통과한다(D3 반영).
- PRD 완료 기준 6·8을 통과한다.

**자동 검사**
- 단위: 메일 제목(`(미정)` 포함)과 본문(스크립트 없음), 반송 해석(실제 표본), 잠금이 한 번만 걸리는지, 이미 보낸 주소를 빼는지, 허용 목록 밖 주소를 막는지.
- 흐름 (가짜 메일):
  - 보내기 연타 → 1통만 나간다.
  - "확인 중"이 결과로 바뀐다.
  - 부분 실패 → 실패한 주소만 다시 보낸다.
  - 접수 거절 → 확인 화면에 머물고, 고친 내용이 남아 있다.
  - 결과 화면에서 뒤로 가기 → 확인 화면으로 가지 않는다.

**화면에서 확인할 행동 → 예상 결과**
1. `MAIL_ALLOWLIST`에 내 메일 주소 2개와 없는 주소 1개를 적는다. 이 세 주소로 A를 진행하고, 발송 확인 창의 「보내기」를 빠르게 두 번 누른다 → 곧바로 결과 화면이 열리고 3개 주소가 "확인 중"이다. 이 표시는 모양을 검토한다(D1).
2. 2분 안에 결과가 바뀐다 → 내 주소 2개는 "보냄", 없는 주소는 "보내지 못함(주소를 찾을 수 없음)".

4. 「실패한 주소에 다시 보내기」를 누른다 → 앞의 두 주소는 메일을 또 받지 않는다.
5. 뒤로 가기를 누른다 → 확인 화면으로 돌아가지 않는다.
6. 편집으로 고친 기한이 메일 본문과 첨부에 "(수정됨)"과 함께 들어 있다.
